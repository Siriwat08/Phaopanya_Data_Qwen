rev.2 นี้เกิดจากอะไร
--------------------
  ผู้ใช้ให้อำนาจเต็มที่จะ "เก็บของดี / เสริม / ลด / ลบ" โดยอ้าง:
  1) ข้อตรวจชุดโค้ดจาก AI อีก 3 ฝ่าย (Grok 1/2/3) — ทั้งสามยืนยัน
     ตัวเลขฐานของเราตรงไฟล์จริงทุกตัว แต่ไม่รับ "กดทำจริงทั้งก้อน"
  2) code review ย้อนกลับของเราเอง พบบั๊กแฝง 2 ตัวที่ต้องแก้จริง:
     - ฉบับแรกเขียน MATCH_KEY ด้วยการ "ต่อข้อความ" แต่ระบบจริงใช้ makeKey()
       ซึ่งตัดคำนำหน้าเขตที่ติดต้นที่อยู่อีกชั้น → แถวที่ ADDR ขึ้นต้นด้วย
       "เขต/แขวง..." จะได้ key ต่างจากปุ่ม 1 = รูที่ทำให้เกิด duplicate
     - ฟังก์ชันอ่านชีตแปลง Number เป็น String ทุกค่า → เฟสที่เขียนทั้ง
       คอลัมน์กลับ (เช่น U ของเฟส 2) จะเปลี่ยนชนิดข้อมูลทั้งคอลัมน์
       บน production โดยไม่ตั้งใจ

  ทุกการเปลี่ยนแปลงผ่านชุดทดสอบกับข้อมูลจริง 11,961 แถวอีกครั้ง:
  ผ่าน 138/138 รายการ (โหลด 00_CleanService.gs ของ production จริงลง
  ตัวทดสอบด้วย — makeKey เป็นตัวจริง ไม่ใช่จำลอง)
